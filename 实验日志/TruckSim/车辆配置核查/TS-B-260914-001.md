惯量数值与均匀长方体公式相符。例如

\[
I_{xx}=\frac{m}{12}(W^2+H^2)
=\frac{18340}{12}(2^2+2^2)

\]

这说明 TruckSim 当前按照均匀刚性箱体自动计算惯量。它适合作为“刚性液货”接口测试，但不能表示部分充液时的自由液面、液体静态质心和晃动惯量。

## 挂车子树与连接类型核查

第三张截图进一步显示：

- 轮胎数据集：`Vehicle Unit with 3 Axles: 3000 kg Tridem (510mm), Duals`；
- 三组固轴悬架运动学、顺从性/弹簧/阻尼和制动子项；
- 挂车簧载质量：`3A European Trailer`；
- 连接数据集：`Hitch: Joint Assembly: Pintle Hitch`。

其中 `Pintle Hitch` 是阻断性疑点。TruckSim 官方 2022 新特性说明区分：`OPT_HITCH_TYPE=1` 为 generic/fifth-wheel，`OPT_HITCH_TYPE=2` 为 ball/pintle；后者连接两点且不计算基于连接角的力矩。因此，若当前连接确为 type 2，它不能直接替代本研究假定的第五轮牵引销连接。

在连接页面确认之前，不继续冻结挂车侧倾、鞍座滚转刚度或轴荷传递模型，也不把当前模板称为“罐式半挂车”。

第四张截图选中的是父级连接数据集下面的 `Animator: Shape File Link: Hitches: Pintle Hitch`。右侧页面标题为 `Animator: Shape File Link`，可见三维资源路径：

```text
Animator\3D_Shape_Files\Common_Vehicle_Assets\Hitches\Pintle_Hitch\pintle_hitch.obj
```

该证据只确认动画中使用了 pintle hitch 的外观文件；此页面只设置形状、颜色、缩放、位置和姿态，不能确认连接动力学采用的 `OPT_HITCH_TYPE`，也不能据此判断角度约束或力矩传递。因此阻断项仍未解除。

第五张截图已进入正确的 `Hitch: Joint Assembly` 父级页面。页面顶部 `Generic or fifth-wheel hitch with torsional resistance` 复选框清楚显示为未勾选，底部关联数据集仍是 `Hitches: Pintle Hitch`。结合 TruckSim 2022 官方模型定义，当前配置应按 ball/pintle 连接处理，不能作为研究模型所需的第五轮连接。截图没有直接显示 `OPT_HITCH_TYPE` 数值，因此日志不把具体数值记为“直接观测”，但已经足以判定当前连接设置不合格。

官方说明指出：generic/fifth-wheel（`OPT_HITCH_TYPE=1`）计算 Y-X-Z 相对转角及相应连接力矩；ball/pintle（`OPT_HITCH_TYPE=2`）只通过作用力连接两点，不根据连接角计算力矩。这一差异会影响牵引车—半挂车之间的侧倾载荷传递和预警时序，不能作为外观差异忽略。

第六张截图确认新连接数据集已经创建：窗口标题为 `{Tanker Research} Tanker_FifthWheel_Hitch`，页面输入区由只读灰色变为可编辑黄色，且 `Delete` 按钮可用。顶部 generic/fifth-wheel 复选框仍未勾选，说明副本尚未切换连接模型，符合“先复制、后修改”的预期。

左侧车辆树暂时仍显示 `Hitch: Joint Assembly: Pintle Hitch`。仅凭当前截图不能判定这是树视图未刷新，还是当前 Run Control 仍链接旧数据集，因此将 `hitch_copy_linked_to_run_control` 保持为 `unverified`。

第七张截图是在点击树视图 `Refresh` 后取得。窗口标题恢复为 `Pintle Hitch [L]`，复选框也重新变为灰色只读状态，左侧树仍为 `Hitch: Joint Assembly: Pintle Hitch`。因此可以确认：新建的 `Tanker_FifthWheel_Hitch` 数据集没有回连到当前 Run Control/车辆组合。

更重要的是，现有组合名称为 `3A Cab Over w/ 3A Euro Trailer`，物理连接为 pintle，并且连接示意点位于牵引车车架后部。它不是已经配置好的第五轮连接基线。是否属于全挂车或中置轴挂车还需通过 TruckSim 组合库和车辆几何页确认，但当前证据已经足以停止“只把 pintle 复选框改成 fifth-wheel”的做法；否则可能保留错误的牵引点位置、轴荷分配和连接拓扑。

第八张截图确认已经返回 `Tanker_6Axle_5DOF_Base` 的 Run Control 页面。当前蓝色车辆组合选择栏仍显示 `3A Cab Over w/ 3A Euro Trailer`，但候选列表尚未展开，因而还不能判断库中是否已有更合适的 tractor–semitrailer 基线。

第九张截图显示 Loaded Combination 库中明确存在 `Cab-Over Tractor-Trailers`、`Day-Cab Tractor-Trailers` 和 `Sleeper-Cab Tractor-Trailers` 分类，同时还将 `Rigid Truck and Dog Trailer Combinations` 单列。这说明软件已提供专门的牵引车—挂车组合类别，不必优先从刚性货车/牵引钩组合手工改造。当前截图只显示一级分类，尚未显示 `Cab-Over Tractor-Trailers` 下的具体轴型和挂车车型。

第十张截图显示 `Cab-Over Tractor-Trailers` 子菜单。与本研究最相关的候选为：

| 候选 | 轴数 | 用途 |
|---|---:|---|
| `3A Cab Over w/ 3A Euro Trailer` | 3+3=6 | 当前六轴基线，但已发现其连接链接为 `Pintle Hitch`，必须继续核查 |

子菜单分类名本身不能证明具体连接类型；必须进入候选车型树检查 Hitch 数据集。因此当前六轴模型既不直接废弃，也不立即冻结。

第十一张截图仍显示 `Vehicle: Loaded Combination: 3A Cab Over w/ 3A Euro Trailer`、`Lead Unit with 3 Axles`、`Trailer with 3 Axles: 3A European Trailer` 和 `Hitch: Joint Assembly: Pintle Hitch`。因此 `2A Euro+3A Trl` 没有被选中，五轴对照切换尚未发生。不能把这张图当作五轴车型的 Hitch 证据。

更正记录：第十二张截图提供了更完整且直接的证据，窗口标题为 `{Cab-Over Tractor-Trailers} 2A Euro+3A Trl [L]`，页面说明为 `2A Cab-Over Tractor + 3A Trailer (I_S + SSS)`；左侧树同步显示 `Lead Unit with 2 Axles: 2A Euro Cab (I_S)` 和 `Trailer with 3 Axles: 3A European Trailer`。因此五轴对照已经成功选中。第十一张截图只代表切换前/返回旧 Hitch 时的页面状态，不再用于判断当前选择。

五轴对照的 Trailer 子树仍明确链接 `Hitch: Joint Assembly: Pintle Hitch`。由此可知，从六轴候选换成五轴候选并不会自动获得 fifth-wheel 连接；两种组合共享或采用相同的 `3A European Trailer`/Pintle Hitch 链路。五轴候选不具备连接模型优势，因此没有必要为了连接问题改变既定六轴研究对象。

## 当前结论

旧项目关于“六轴牵引车—三轴半挂车”的表述得到初步支持。现有 `Fz_L1` 至 `Fz_L5` 导出模板不足以直接证明覆盖六轴，必须在 TruckSim 中逐项核对全部车轴轮载变量。

当前运行控制页属于 Active Transfer Case Control 示例，不能直接视为正式液罐半挂车模型。为保护示例和保持研究可追溯性，应先 `Duplicate` 创建独立研究数据集，再修改车辆质量、质心和挂车参数。

2026-09-14 补充证据确认：独立数据集 `Tanker_6Axle_5DOF_Base` 已创建；原示例说明文字仍保留，但后续修改不会直接覆盖原 Run Control 数据集。当前 18,340 kg 箱形载荷只能作为模板初值，不能直接解释为液体质量或某一充液率。

载荷参数页进一步确认，该 18,340 kg 载荷是 7.5 m × 2.0 m × 2.0 m 的均匀长方体，质心高 2.3 m。后续不能只把质量改为三个充液率而保留其质心和惯量不变；每个充液率必须由统一罐体几何和液体密度重新计算。
